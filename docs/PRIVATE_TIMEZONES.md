# Приватные часовые пояса

Выполнить целиком `supabase/migrations/202611070007_private_timezones.sql` в Supabase SQL Editor после sharing migration 005. Если используется 006, порядок: 006 → 007. Повторный запуск 006 после 007 вернёт публичное поле; в таком случае повторить 007.

007 удаляет часовой пояс автора из JSON ответов публичного расписания и расписания в профиле. Профиль поиска и список друзей уже используют явный список полей без timezone. Свой `yn_social_home` сохраняет приватное поле для настроек владельца. Публичные эфиры содержат абсолютный startsAt (UTC), но не исходные date/time/timeZone. Клиент отображает их во времени посетителя, не предлагает пояс автора и не показывает название города. Сообщения также используют собственную настройку времени.

GPS, координаты и IP-геолокация не используются. Начальное значение — Intl.DateTimeFormat().resolvedOptions().timeZone устройства; сохранённый выбор можно изменить в настройках. Пояс сам по себе не устанавливает точное местоположение.

Важно выполнить SQL: скрытие поля интерфейсом не удаляет его из старого RPC. Проверки Node покрывают отсутствие исходного пояса в HTML и конверсию времени посетителя. SQL регрессия `supabase/tests/private_timezones.sql` подготовлена, но в этой среде не запускалась.
