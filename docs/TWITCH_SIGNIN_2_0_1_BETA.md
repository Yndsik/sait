# Вход через Twitch — RIVLO 2.0.1 бета

Код интерфейса готов; настоящий OAuth заработает после настройки вашего Twitch-приложения и провайдера Supabase. Client Secret нельзя присылать в чат или добавлять в репозиторий/публичные переменные. Новая SQL-миграция для входа не нужна.

## 1. Twitch Developer Console

1. Откройте https://dev.twitch.tv/console/apps и войдите в аккаунт Twitch.
2. Если создание приложения недоступно с ошибкой про two-factor authentication, включите 2FA: https://www.twitch.tv/settings/security . Вернитесь в консоль.
3. Нажмите **Register Your Application**. Можно использовать уже созданное приложение RIVLO вместо нового.
4. Name: `RIVLO`. Category: **Website Integration** (или ближайшая категория веб-сайта). Client Type: **Confidential**, если это поле доступно: обмен кодом выполняет Supabase, а не браузер.
5. В **OAuth Redirect URLs** добавьте точный адрес:

   `https://ougbjjfrxfokyqqriqtx.supabase.co/auth/v1/callback`

   Это адрес Supabase, не Cloudflare и не главная RIVLO. Нажмите **Add**, затем сохраните приложение.
6. Откройте **Manage** приложения. Скопируйте **Client ID**, создайте **Client Secret** и сохраните его в менеджере паролей. Вставлять Secret нужно только в Supabase на следующем шаге.

## 2. Провайдер Twitch в Supabase

1. Откройте https://supabase.com/dashboard/project/ougbjjfrxfokyqqriqtx/auth/providers . Если путь в интерфейсе изменился: проект → **Authentication → Sign In / Providers → Twitch**.
2. Включите **Enable Sign in with Twitch**.
3. Вставьте Twitch **Client ID** и **Client Secret** в соответствующие поля. Сохраните.
4. Сверьте показанный Supabase Callback URL с адресом из шага 1. Они должны полностью совпадать.
5. Не выключайте провайдер Email и подтверждение почты ради OAuth. Не отключайте CAPTCHA для email-регистрации. Twitch-вход использует авторизацию на стороне провайдера.

Для этого входа не нужны Twitch-ключи в Cloudflare, service_role key или ключи в `auth-config.js`. Серверные переменные глобального поиска Twitch — отдельная возможность, здесь их не меняем.

## 3. URL возврата в RIVLO

1. Откройте https://supabase.com/dashboard/project/ougbjjfrxfokyqqriqtx/auth/url-configuration (**Authentication → URL Configuration**).
2. **Site URL**: `https://yndsi-streamer-hub.pages.dev`.
3. Сохраните прежние нужные Redirect URLs и добавьте:

   - `https://yndsi-streamer-hub.pages.dev/`
   - `https://yndsi-streamer-hub.pages.dev/?auth=twitch`
   - `https://yndsi-streamer-hub.pages.dev/?twitch=linked` — для прежней привязки в приватности.

4. Если Supabase отклоняет возврат с query-параметром, допустим шаблон `https://yndsi-streamer-hub.pages.dev/**` только для этого доверенного хоста. Не разрешайте `https://**` и чужие домены. Код RIVLO всегда запрашивает фиксированный возврат на свой текущий origin.
5. Для превью/localhost добавляйте только конкретные используемые адреса; основной production-адрес менять не нужно. Открывать старый Netlify ради настройки не требуется.

## 4. Существующие email-аккаунты и привязка

Supabase автоматически связывает поддерживаемые identities при совпадении доверенного подтверждённого email. RIVLO не объединяет аккаунты по строке email и не создаёт второй профиль вручную. При успешном объединении UUID пользователя и постоянный ID RIVLO должны сохраниться.

Если Supabase вернул конфликт (`identity_already_exists`, `email_exists` и подобные), интерфейс предложит **войти по email**, затем открыть **Приватность → Подключить Twitch**. Для этой явной привязки в Supabase нужно включить **Allow manual linking** в настройках Auth identity linking (Authentication → Sign In / Providers, раздел настроек аккаунтов; название пункта зависит от версии панели). Это прежний сценарий `linkIdentity`, требующий входа в существующий аккаунт. Не удаляйте существующего пользователя и не переносите его UUID ради обхода ошибки.

Если Twitch уже принадлежит другому аккаунту RIVLO, сначала нужно войти в тот аккаунт и разобраться с привязкой. Автоматического переноса чужой identity нет. При разных email используйте явную привязку из уже открытого email-аккаунта.

## 5. Что сохраняется

После входа клиент повторно получает пользователя через Supabase `getUser()` и читает только identity `provider=twitch`:

- `db.profile.twitch_id` — числовой provider ID;
- `db.profile.twitch_login` — логин Twitch;
- `db.profile.twitch_avatar` — URL фото на `https://static-cdn.jtvnw.net`.

Поля сохраняются существующим механизмом в приватный JSON `user_workspaces.data.profile`. Редактор профиля сохраняет их при редактировании. Свой профиль показывает отдельную карточку Twitch с аватаром и логином. Ник и аватар RIVLO остаются пользовательскими: вход не заменяет их, не выдаёт галочку и не включает публичный поиск. Новый пользователь проходит прежнее первичное заполнение RIVLO-профиля. Эти копии полей не считаются серверным доказательством владения каналом: прежний каталог стримеров проверяет `auth.identities` на сервере.

Токены Twitch не записываются в профиль и отфильтровываются из сохранённой сессии RIVLO. Запрашивается только `user:read:email`, необходимый провайдеру Supabase; фолловеры, VOD, чат и статистика Twitch не импортируются. Имя, email и авторизация по паролю обрабатываются Supabase как раньше.

## 6. Проверка после ручной настройки

1. Откройте сайт в отдельной вкладке/приватном окне. Локальный режим должен открываться и сохранять черновик без входа.
2. Откройте **Войти**, затем **Регистрация**: кнопка **Войти через Twitch** должна быть на обеих вкладках. Для восстановления пароля она скрыта.
3. Нажмите кнопку с пустыми полями email и пароля. Откроется официальный Twitch. Разрешите вход. Возврат — в RIVLO; технические callback-параметры очищаются.
4. Для нового пользователя заполните RIVLO-профиль. В своём профиле проверьте карточку Twitch. Перезагрузите страницу; в приватном JSON должны сохраниться три поля выше.
5. Для существующего email-пользователя до проверки запишите постоянный ID и проверьте игры/заметки. После OAuth с тем же подтверждённым email или явной привязки UUID/ID и данные должны остаться прежними. Ник/аватар RIVLO не меняются.
6. Отмените OAuth или откажите в доступе. Показывается понятное сообщение, можно повторить вход, войти по email или продолжить без входа. Локальный черновик не удаляется.
7. Проверьте конфликт уже привязанного Twitch: получите подсказку про вход по email/приватность, а не новый аккаунт.
8. Проверьте RU/EN, ширину 360 px и «Запомнить меня»: настройка действует и для Twitch-сессии. При ошибке конфигурации email-вход остаётся рабочим.

В разработке проверены локальные модели и Chromium с подставным SDK/OAuth-сервером: успех для нового и существующего пользователя, ошибки/отмена, сохранение профиля, remember-me, локальный режим, email, RU/EN и мобильная верстка. Настоящая Twitch-авторизация требует ваших ключей в Supabase и отдельной проверки после настройки; реальные ключи в этой сессии не использовались.

## Откат

Веб-версия остаётся **2.0.1 бета**, новая всплывающая версия не создаётся. Для возврата к **2.0.0** используйте прежний production commit `815bc58b6d81264b672d5d25a444023151928be7` (PR #31), откатив последующие beta PR в обратном порядке. SQL/пользователей удалять не нужно. Настройка провайдера Supabase не откатывается коммитом: при необходимости выключите Twitch Sign In вручную, сохранив Email и существующие аккаунты. Уже связанные identities не удаляйте ради отката интерфейса.
