# Друзья и личный чат — подключение с iPhone

Эта версия добавляет несколько пользователей только для общения. Регистрацию НЕ включать. Существующая owner-only политика user_workspaces сохраняется; Steam API, библиотека, заметки, задачи и расписание доступны только владельцу.

## 1. База данных

В GitHub открой supabase/migrations/202611070001_friends_chat.sql → скопируй весь SQL. В Supabase → SQL Editor → New query → вставь → Run. Подставлять UUID и ключи не нужно. Сначала должна быть выполнена прежняя миграция владельца, как в текущем проекте.

Миграция создаёт закрытые таблицы в yndsi_private и семь RPC. У anon и authenticated нет прямого доступа к таблицам; RLS включён без клиентских политик. SECURITY DEFINER RPC работают с пустым search_path, допускают только владельца и пользователей с auth.users.invited_at (приглашённых администратором), определяют пользователя только через auth.uid(), проверяют участников дружбы и не возвращают email/UUID профиля. ID поиска — 12 случайных hex-символов, глобального списка пользователей нет. ID не заменяет подтверждение заявки.

Новая миграция ещё не была запущена в живом проекте из среды Codex. PostgreSQL/Docker недоступны для интеграционного теста в этой среде. Дополнительный транзакционный сценарий supabase/tests/social_access.sql можно выполнить целиком после миграции: он создаёт четыре тестовых аккаунта в транзакции, проверяет доступ и выполняет ROLLBACK. Если запрос падает, нажми ROLLBACK отдельным запросом; не коммить тестовую транзакцию.

## 2. Доступ друзей

Supabase → Authentication → URL Configuration → Additional Redirect URLs: добавь точные адреса основного сайта и Deploy Preview, например https://deploy-preview-1--reliable-unicorn-7ce032.netlify.app/ и https://reliable-unicorn-7ce032.netlify.app/. Site URL должен вести на актуальную проверяемую версию: основной сайт до слияния PR ещё старый.

Supabase → Authentication → Users → Add user → Invite user: введи email друга и используй redirect на проверяемый сайт, если поле доступно. Если приглашение возвращает на Site URL, на время теста выбери там точный URL Deploy Preview. Приглашения отправляет владелец через Supabase; приложение не имеет service_role и само не рассылает письма.

Друг открывает приглашение, попадает в «Друзья», открывает «Ник и аватарка», задаёт имя и новый пароль (минимум 10 символов). Если письмо не пришло, проверь лимиты почты Supabase и настройки SMTP. Не публикуй пароли/токены и не включай публичную регистрацию ради обхода приглашения.

## 3. Проверка с двумя аккаунтами

1. Войди своим аккаунтом. В «Друзья» создай профиль для общения; ник и иконка используются также в рабочем профиле владельца; описание для друзей заполняется отдельно и не раскрывает личные записи.
2. Друг входит по приглашению и копирует свой ID. Найди его по ID → «Добавить в друзья».
3. Друг нажимает «Обновить» в списке и принимает входящую заявку. Затем обоим доступна кнопка «Написать».
4. Отправьте сообщения в обе стороны, обновите страницу, проверьте историю и загрузку более ранних сообщений. Чат проверяет новые сообщения каждые 5 секунд, только когда страница видна. Это polling, не presence: статус «онлайн» пока не показывается.
5. Проверь блокировку: новые сообщения и чтение истории должны стать недоступны. Разблокировать может только заблокировавший. При повторном добавлении в друзья прежняя история снова доступна; удаление из друзей не уничтожает переписку.
6. У друга в меню должен быть только раздел «Друзья». Прямой запрос к user_workspaces должен возвращать ноль строк, Steam Function — 403. Скрытое меню не является защитой: серверные проверки и RLS остаются обязательными.

## Ограничения первой версии

Текстовые личные сообщения до 2000 символов; без вложений, звонков, групп, push и сквозного шифрования. Сервер ограничивает отправку одним сообщением в секунду на пользователя. При ошибке текст остаётся в поле. Черновики хранятся только в памяти страницы; выход очищает их. История загружается по 40 сообщений, максимум 400 в открытой сессии; более старые записи остаются в БД. Блокировка выключает доступ к истории, но не удаляет сообщения. Публичный профиль виден по точному ID и связанным пользователям. Новые входящие заявки показываются после «Обновить».

Новых Netlify переменных или Steam ключей не требуется. Публикация production выполняется только после проверки миграции, приглашения, изоляции аккаунтов и чата в Deploy Preview.

При первом открытии нового профиля показывается предложение выбрать ник и аватарку вместо стандартного имени «Игрок». В форме есть предпросмотр. У владельца сохранение ника/аватара в настройках обновляет публичную идентичность, если социальный профиль загружен; ошибка RPC не скрывается и не подтверждается как успешное сохранение. При первом создании публичного профиля предлагаются ник и фото рабочего профиля, публикация происходит после нажатия «Сохранить». Числовой/hex ID стабилен и не меняется вместе с ником. Боковая панель прокручивается независимо от основной страницы и учитывает высоту мобильного окна.
