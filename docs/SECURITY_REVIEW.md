# Проверка безопасности 6 ноября 2026

Область: исходники текущего YNDSI, Auth, публичная сборка, serverless Steam, сохранённые SQL/RLS/Storage-политики. Проверка статическая и локальные негативные тесты; не независимый pentest и не доказательство безопасности production.

| Наблюдение | Результат |
|---|---|
| Netlify публиковал корень проекта вместе с SQL/тестами/документацией | Исправлено явной сборкой dist. Репозиторий публичный, поэтому это уменьшение поверхности, не утечка ранее секретного кода. |
| Не было CSP/HSTS/Permissions-Policy | Добавлены; unsafe-inline пока остаётся из-за структуры приложения. |
| CAPTCHA отсутствовала | Готов виджет, передача captchaToken для signUp/signIn и запрет отправки при непройденной/истёкшей проверке. Нужны Site Key в сборке и Secret Key + CAPTCHA protection в Supabase. |
| Лимит Steam был локальным Map после auth-запроса | Добавлены локальная обратная нагрузка, ранняя проверка запроса, локальное ограничение auth по доверенному Netlify IP и атомарная общая квота (SQL + env, ещё нужно включить). |
| Заявки друзьям без общего ограничения частоты | Подготовлен серверный trigger 20/мин; сообщения дополнительно ограничены 60/мин. SQL не выполнен этой средой. |
| Личные данные | В сохранённых миграциях собственный workspace защищён RLS; social RPC проверяет подтверждённую сессию и дружбу; Storage приватный, ограничены MIME/размеры и права чтения; публичный профиль/расписание используют явные поля. Фактическое состояние production не подтверждено. |
| Публичный Supabase publishable key | Допустим по назначению; безопасность зависит от RLS, не скрытия этого ключа. service_role в клиент не добавлялся. |
| Доступ к работающему серверу | Проверка HTTP не выполнена: proxy:8080 недоступен. Нет административных подключений Netlify/Supabase и настроенных секретов среды. |
| DDoS | Нагрузочные атаки не проводились. Нужны проверка WAF/edge rate limiting, лимиты Auth и мониторинг провайдера. |

Локальные проверки покрывают отрицательные сценарии авторизации, изоляцию локальных сессий, экранирование сообщений, лимиты/типы вложений, анонимный публичный viewer, CAPTCHA lifecycle и передачу токена, общий quota fail-closed с подменёнными ответами, ограничение параллелизма и отсутствие служебных файлов/секрета в dist. SQL-регрессии подготовлены, но здесь не запускались. Установка CAPTCHA, Auth/WAF-политик и миграций требует действий владельца по SECURITY_SETUP.md.
