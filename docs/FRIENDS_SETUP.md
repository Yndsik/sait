# Друзья, постоянный ID и единый профиль

Публичная регистрация остаётся выключенной. Владелец приглашает друзей через Supabase. Библиотека, заметки, задачи, Steam API и расписание доступны только владельцу; приглашённым пользователям доступны «Друзья» и «Настройки профиля».

## Подключение базы с iPhone

1. Если ещё не выполнено: Supabase → SQL Editor → New query → вставить целиком `supabase/migrations/202611070001_friends_chat.sql` → Run. Владелец уже подтвердил выполнение этой миграции.
2. Выполнить там же **новый** файл `supabase/migrations/202611070002_identity_onboarding.sql`. Подставлять UID или ключи не нужно. Он не заменяет существующие ID, не удаляет друзей и сообщения.
3. После сборки Netlify обновить Deploy Preview. Новые функции БД ещё не были запущены из среды Codex: административного подключения к Supabase нет.

Социальные таблицы закрыты в `yndsi_private`, RLS включён, прямых прав на таблицы у anon/authenticated нет. RPC используют auth.uid(), проверяют владельца/приглашение, участников дружбы и блокировку. Поиск только по полному ID, глобального списка пользователей нет.

## Как устроен профиль

ID создаётся на сервере, когда создаётся приглашённая учётная запись (или ей присваивается invited_at). Для существующих разрешённых аккаунтов ID добавляется, только если его ещё нет. ID закреплён за auth.users.id на всё время существования этой учётной записи. Он не меняется при выходе, повторном входе, перезагрузке, смене устройства, ника или аватарки. Отдельный DB-триггер запрещает UPDATE ID и user_id; поля ID нет в редактируемой форме.

После первого входа пользователь автоматически попадает в настройки: придумывает ник и загружает фото либо оставляет инициалы. Нажимает «Сохранить и начать» — сервер отмечает завершение первоначальной настройки. Последующие входы этот экран не повторяют. Уже настроенные профили сохраняются; стандартный пустой «Игрок» считается ненастроенным.

Менять ник и аватар можно **только в настройках профиля**, доступных через меню или верхнюю аватарку. В друзьях/чатах нет форм редактирования. Там отображается сохранённая серверная идентичность. ID можно скопировать, но нельзя изменить. Для владельца описание рабочего профиля остаётся личным; публичное описание не подменяется личными заметками. Для друзей описание в настройках — публичное.

Фото: JPEG/PNG/WebP до 8 МБ, центральная обрезка до 256×256, сохранение WebP в закрытой записи профиля. SVG и внешние URL не принимаются. Пароль меняется отдельной формой «Безопасность аккаунта» в настройках, не в чате.

## Приглашение друга

Supabase → Authentication → URL Configuration: добавь точные URL тестового и основного сайтов в Redirect URLs. Site URL должен вести на текущую проверяемую версию (до слияния PR основной сайт может быть старым).

Authentication → Users → Add user → Invite user → email друга. Если доступен Redirect URL — выбери Deploy Preview; иначе ссылка вернёт на Site URL. Приглашение отправляет владелец через Dashboard; приложение не получает service_role и само не рассылает письма.

Друг открывает приглашение → задаёт ник и аватар в первоначальной настройке → «Сохранить и начать». В настройках также нужно задать собственный пароль для последующих входов. При проблемах с доставкой проверь SMTP и почтовые лимиты Supabase; не включай публичную регистрацию для обхода приглашения.

## Проверка перед публикацией

- Скопировать свой ID, сменить ник/фото через настройки, обновить страницу, выйти и войти: ID должен остаться тем же, ник/фото — восстановиться.
- Пригласить второй аккаунт: при первом входе должна открыться настройка профиля; после сохранения и повторного входа настройка не повторяется. У второго аккаунта только «Друзья» и «Настройки»; запрос user_workspaces возвращает ноль строк, Steam Function — 403.
- Найти второго пользователя по ID, отправить заявку, принять её с другого аккаунта. Проверить свои ники/фото в списках и заголовке чата.
- Отправить сообщения в обе стороны, перезагрузить, проверить историю, блокировку и недоступность сообщений/истории после блокировки.
- Прокрутить боковое меню на iPhone до последнего пункта. Панель имеет собственную прокрутку и учитывает safe-area.

Дополнительный тест `supabase/tests/social_access.sql` запускается целиком ПОСЛЕ обеих миграций. Он создаёт четыре тестовых аккаунта в транзакции, проверяет назначение и неизменность ID, сохранение профиля, доступ к чатам/блокировку и заканчивается ROLLBACK. Он не был выполнен в среде Codex: PostgreSQL/Docker недоступны. Не заменять ROLLBACK на COMMIT.

## Границы версии

Личные текстовые сообщения до 2000 символов. Проверка новых сообщений каждые 5 секунд только на видимой странице. Без статуса онлайн, групп, вложений, звонков, push и сквозного шифрования. История загружается по 40, до 400 в открытой сессии; более старые сообщения остаются в БД. Удаление из друзей/блокировка закрывают доступ к истории, но не удаляют её; после новой дружбы она снова доступна. Входящие заявки появляются после «Обновить». Черновики — только в памяти страницы, выход их очищает.

Новых Netlify переменных не требуется. Production пока не публикуем: сначала проверяем миграцию, постоянный ID и два аккаунта в Deploy Preview.
