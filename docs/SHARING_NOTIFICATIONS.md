# Публичное расписание, уведомления и анимации

## Подключить с iPhone

Supabase → SQL Editor → New query → выполнить целиком `supabase/migrations/202611070005_sharing_notifications.sql` после предыдущих миграций. Никаких UUID/ключей подставлять не нужно. Новых Netlify переменных нет. Новые функции и SQL ещё не проверены на живой базе из Codex: административного подключения нет. Production обновлять после проверки Deploy Preview.

## Приватность расписания

Настройки профиля → «Приватность расписания». По умолчанию публикация выключена, эфиры не выбраны. Пользователь выбирает до 100 запланированных эфиров, включает публикацию и сохраняет. Перед публикацией клиент ждёт сохранения рабочего пространства; сервер читает только workspace текущего auth.uid().

Публичны только ник, аватар, название выбранного эфира, игра и время. Не публикуются user_id, личное описание, заметки, чек-листы, планы эфиров, задачи, библиотека и невыбранные стримы. SQL хранит отдельную проекцию и отслеживает только выбранные ID: сохранённые изменения их названия/игры/времени обновляются автоматически, отменённые/удалённые эфиры исчезают. Новые эфиры сами в публикацию не попадают. Изменение только личных заметок не меняет время обновления публичной проекции.

«Скрыть расписание» сразу выключает доступ и меняет токен. «Новая ссылка» меняет токен активной публикации; старая ссылка перестаёт работать. Токен публикации не имеет отношения к постоянному ID аккаунта. Перепривязка публичного URL не меняет ID пользователя.

Ссылка вида `/schedule.html?s=<uuid>` открывается без регистрации и не использует сохранённую сессию. Можно выбрать Атырау (UTC+5) или часовой пояс устройства. Страница запрашивает свежие данные раз в минуту в видимой вкладке. Отзыв ссылки запрещает последующие запросы; уже увиденные/скопированные посетителем данные невозможно отозвать. Ссылку может переслать любой её получатель. Страница не индексируется (noindex), не передаёт Referer и не кешируется как HTML. Это не защита паролем.

В карточке профиля появляется «Расписание стримов» только при включённой публикации. Блокировка скрывает ссылку при просмотре профиля, но известная публичная ссылка остаётся доступна анонимно до отключения публикации.

## Уведомления

Колокольчик в верхней панели и счётчик в меню «Друзья» показывают количество непрочитанных сообщений из принятых чатов. Новые сообщения проверяются каждые 10 секунд на всех разделах сайта. Первоначально накопленные непрочитанные показываются счётчиком без всплывающего шквала старых уведомлений. При новом сообщении появляется баннер; нажатие открывает нужный чат. Центр уведомлений доступен по колокольчику.

Непрочитанные позиции хранятся в закрытой таблице по пользователю и собеседнику. Открытый видимый чат отмечается прочитанным, только когда пользователь находится у последних сообщений. Скрытая вкладка не отмечает прочтение. В API уведомлений нет текста сообщений; браузерные уведомления содержат только имя отправителя и факт нового сообщения. Собеседнику не показывается время прочтения.

Настройки профиля → «Уведомления и приватность»: баннеры сайта и отдельное разрешение браузера. Предпочтения хранятся локально для аккаунта на этом устройстве. Разрешение ОС/браузера запрашивается только по нажатию переключателя. При выходе из аккаунта баннеры, счётчики и объекты уведомлений очищаются.

ВАЖНО: эта версия проверяет сообщения, пока сайт открыт; браузер может замедлять таймеры фоновой вкладки. При закрытом сайте push не отправляются. На iPhone/Safari обычной вкладке системные уведомления часто недоступны; интерфейс это обозначает. Для полноценного фона понадобится отдельный Web Push/PWA с service worker, подписками и серверной доставкой. Не включаем фиктивное «push подключён».

## Анимации и иконки

Чат получил SVG-иконки, короткую анимацию новых пузырей, появления диалогов/уведомлений, мягкие нажатия кнопок и плавное затемнение мобильного меню. Это поведение в стиле мессенджера с визуальной идентичностью YNDSI, без копирования ресурсов Telegram. История при первой загрузке не анимируется как новые сообщения; подгрузка старых не сбивает проигрыватели. prefers-reduced-motion отключает движения.

## Проверка

1. Создать два стрима, выбрать один для публикации. Открыть ссылку в приватной вкладке без входа: видны только выбранный эфир, ник/фото и время; нет заметок и планов.
2. Изменить выбранный эфир, сохранить, обновить публичную страницу. Отменить эфир и проверить исчезновение.
3. Отключить публикацию, обновить старую ссылку: данных нет. Снова включить и убедиться, что старый токен не ожил.
4. С двух аккаунтов отправить сообщение, пока получатель находится в библиотеке: появятся счётчик и баннер. Открыть через баннер, проверить сброс. Проверить прокрутку старых сообщений и отсутствие преждевременной отметки прочтения.
5. Проверить браузерный переключатель на поддерживаемом устройстве, отказ в разрешении, выход/смену аккаунта и уменьшение движения.

Дополнительный `supabase/tests/sharing_notifications.sql` создаёт временных пользователей, проверяет публичную проекцию/anon-доступ, отзыв ссылки и изоляцию уведомлений; завершается ROLLBACK. Выполнять целиком после миграции. SQL-тест не запускался в среде Codex и не заменяет проверку браузера/iPhone.
