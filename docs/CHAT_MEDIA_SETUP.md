# Голосовые, фото, видеокружки и профили

## Подключение

1. Supabase → SQL Editor → New query → выполнить целиком `supabase/migrations/202611070004_chat_media.sql`. Ничего подставлять не нужно. Сначала должны быть выполнены предыдущие социальные и многопользовательская миграции.
2. Скрипт сам создаёт приватный bucket `chat-media`, таблицу вложений, Storage policies и RPC. Не делайте bucket публичным. Дополнительных ключей/переменных Netlify не требуется.
3. Проверить Deploy Preview нового PR до слияния. SQL и настоящие файлы из среды Codex не проверялись: нет административного подключения к Supabase и доступа к аппаратным микрофону/камере iPhone. JS-тесты используют подмены устройств.

## Использование

В принятом личном чате кнопки «Фото», «Голосовое», «Видеокружок». Фото выбирается из галереи, уменьшается до 1600 px по длинной стороне и преобразуется в JPEG. Запись включается только по нажатию и после разрешения браузера. Перед отправкой есть предпросмотр, необязательная подпись и отмена.

Голосовые: автоматическая остановка до 120 секунд, до 10 МБ. Видеокружки: до 30 секунд, до 20 МБ, фронтальная камера; круглая форма отображения. При уходе из чата/выходе/отмене запись и дорожки микрофона/камеры останавливаются. При скрытии вкладки запись останавливается и сохраняется только в предпросмотре. Отдельного серверного транскодинга/проверки реальной длительности содержимого нет: сервер проверяет размер Storage-объекта, MIME и заявленную длительность.

На iPhone открывать в Safari по HTTPS. MediaRecorder/getUserMedia доступны не во всех встроенных браузерах; при отказе в разрешении показывается ошибка. Клиент выбирает поддерживаемый MP4/WebM/OGG. Поддержку записи и воспроизведения между устройствами нужно проверить отдельно.

Входящее медиа загружается по нажатию «Открыть…»/«Прослушать…», чтобы не тратить мобильный трафик автоматически. Кнопка «Обновить доступ» получает новую ссылку, если предыдущая истекла. Текстовые сообщения продолжают работать как раньше; опрос чата не пересоздаёт уже отображённые сообщения и не должен обрывать проигрыватель.

Ник/аватар в списке друзей, поиске и заголовке чата открывают карточку публичного профиля: ник, фото, публичное описание, постоянный ID и действие «Написать»/«Добавить». Рабочее пространство, email и личные заметки не показываются. Редактирование идентичности остаётся только в настройках. Мобильное меню закрывается нажатием на затемнённый фон или Escape.

## Доступ и ограничения

RPC подготовки проверяет принятую дружбу, тип, размер и лимит 60 вложений в час на пользователя. Путь назначается сервером. Отправка фиксируется только после совпадения размера и MIME в Storage; повторный запрос с тем же ID не дублирует сообщение. Фото до 8 МБ, bucket максимум 20 МБ. HTML/SVG запрещены. MIME не является глубокой проверкой содержимого: сообщения отображаются нативными img/audio/video.

Storage INSERT разрешён отправителю подготовленного вложения; UPDATE запрещён; SELECT отправленного вложения требует участия в текущей принятой дружбе. Незавершённый файл может читать/удалять только отправитель. Отдельные restrictive policies ограничивают bucket даже при наличии широких permissive policies других bucket. Блокировка закрывает новые запросы на файлы; уже выданная подписанная ссылка действует до 120 секунд. Переписка не имеет сквозного шифрования.

Отмена удаляет незавершённую загрузку по возможности. При потере сети/закрытии браузера могут остаться pending-записи и объекты, недоступные получателю. Автоматический серверный сборщик мусора пока не настроен: перед увеличением аудитории требуется регулярная очистка pending старше часа через Storage API (не прямое удаление storage.objects) и контроль квоты Storage. Отправленные вложения автоматически не удаляются. Не удаляйте bucket и не меняйте общий public-флаг для исправления ошибки доступа.

## Проверки перед публикацией

- Два подтверждённых аккаунта: заявка → принятие → текст, фото с подписью, голосовое, видеокружок в обе стороны; обновить страницу и проверить историю.
- Отмена разрешения микрофона/камеры, отмена записи до и после выдачи разрешения, переход в другой раздел во время записи: индикатор микрофона/камеры должен погаснуть.
- Воспроизведение при обновлении чата, смена аккаунта и уход из чата: проигрыватели не должны продолжать играть чужую переписку.
- После блокировки новый запрос подписанной ссылки и отправка должны быть недоступны; третий аккаунт не должен читать Storage-объект.
- Открыть профиль по нику/фото, убедиться в отсутствии личных данных и форм редактирования.
- Открыть боковое меню на iPhone, нажать снаружи: меню закрывается без нажатия кнопки под затемнением.

Дополнительный SQL-тест `supabase/tests/chat_media_access.sql` создаёт временных пользователей и только Storage-метаданные внутри транзакции, проверяет доступ/идемпотентность и выполняет ROLLBACK. Он не заменяет настоящую загрузку файлов через Storage API и ещё не запускался в этой среде. Выполнять целиком после миграции.
