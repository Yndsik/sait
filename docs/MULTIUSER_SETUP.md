# Общая платформа с личными пространствами

У каждого подтверждённого или приглашённого пользователя все разделы: Dashboard, расписание, Steam, библиотека, Wishlist, прохождения, заметки, задачи, статистика, друзья и профиль. Каждый читает и изменяет только свою строку user_workspaces: user_id = auth.uid(). Статус владельца не даёт интерфейсу доступа к чужим записям. Друзья и чат по-прежнему требуют подтверждения заявки. Существующие ID, данные и связи не копируются и не удаляются.

## Настройка с iPhone

1. В Supabase → SQL Editor выполнить целиком `supabase/migrations/202611070003_multiuser_workspaces.sql` после предыдущих миграций. Без неё новая версия не открывает рабочее пространство.
2. Дождаться Deploy Preview нового PR. В Netlify существующие SUPABASE_URL/SUPABASE_PUBLISHABLE_KEY должны быть доступны Deploy Previews и Functions; новых переменных нет. OWNER_USER_ID можно оставить для совместимости, но принадлежность всех запросов Steam владельцу больше не требуется.
3. В Supabase → Authentication → URL Configuration добавить точный адрес нового Deploy Preview в Redirect URLs. Site URL для production: https://reliable-unicorn-7ce032.netlify.app/. Регистрация передаёт адрес текущего сайта для письма подтверждения; он должен быть разрешён в Supabase.
4. Authentication → Sign In / Providers → Email: включить **Allow new users to sign up** и оставить **Confirm email** включённым. Это меняет прежнее правило «только по приглашениям». Сначала выполнить SQL и проверить изоляцию, затем открывать регистрацию. Если письма не доходят, проверить SMTP и почтовые лимиты проекта.
5. На Deploy Preview создать второй аккаунт: ник, email, пароль (от 10 символов), подтвердить почту. При первом входе выбрать аватарку и сохранить профиль. У второго пользователя должно быть полное меню, собственная пустая библиотека и личные заметки/расписание. Добавить игру, создать стрим, обновить страницу и проверить сохранение.
6. Выйти и войти владельцем: его прежние данные должны сохраниться, данные второго аккаунта отсутствовать. На том же устройстве несколько раз переключить аккаунты; проверить сохранение изменений и отсутствие переноса чужой библиотеки.
7. Проверить заявки и переписку между аккаунтами. После проверок слить PR: Netlify опубликует main. До слияния production остаётся прежней версии.

## Данные и безопасность

Кэш разделён ключами yndsi_db:<auth-user-id>. Общее старое хранилище yndsi_db может мигрировать только первоначальный владелец, подтверждённый сервером. Новые аккаунты никогда не импортируют эту запись. При выходе/смене аккаунта данные в памяти очищаются, отложенные сохранения предыдущего аккаунта отменяются. Ошибки облака не маскируются успехом; свои изменения остаются в кэше с отметкой dirty. Конфликт локальной и облачной версий требует выбора с резервом для этого же аккаунта.

Регистрация создаёт серверный стабильный ID, но доступ к рабочим/социальным операциям остаётся закрыт до подтверждения почты (или входа по действующему приглашению). Ник и аватар редактируются только в настройках. Дата назначения ID и состояние первоначальной настройки не зависят от устройства.

Steam Function проверяет Supabase-сессию и подтверждение/приглашение. Кэш ограничен; добавлен локальный для экземпляра лимит 30 запросов в минуту на пользователя. Этот лимит не распределён между экземплярами и не заменяет постоянный rate limiter при росте нагрузки.

## Проверки

JS-тесты покрывают полный интерфейс обычного пользователя, изоляцию локальных кэшей, отмену отложенной записи при смене аккаунта, сохранение прежних данных владельца, отказ неподтверждённому пользователю, регистрацию и Steam для обычного аккаунта. SQL-файл `supabase/tests/multiuser_access.sql` проверяет RLS между тремя временными пользователями в транзакции и заканчивается ROLLBACK. Запускать целиком после миграции. SQL-интеграция и новый сценарий регистрации не выполнялись на живом Supabase из среды Codex: административного доступа к базе нет.

Исторические инструкции о скрытом меню друзей и owner-only workspace в предыдущих docs относятся к прежней версии; для общей платформы использовать этот документ.
