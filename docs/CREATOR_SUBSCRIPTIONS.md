# Подписки, подтверждение стримера и онлайн

После публикации выполните в Supabase SQL Editor миграции:
1. `supabase/migrations/202611080012_creator_subscriptions.sql` после существующих 001–009.
2. `supabase/migrations/202611080014_visitors_subscriber_counts.sql` после 012. Эта миграция включает гостей в общий счётчик и добавляет число подписчиков. Таблица social_presence и SQL 009/013 ей не нужны. Также сохраняет просмотр окна обновления для аккаунта.

SQL не выполняется автоматически при публикации сайта. До подключения новых RPC галочки и подписки недоступны, онлайн отображает «—», а не выдуманное число.

## Проверка канала владельцем сайта

После SQL 014: войдите в аккаунт владельца → «Мой профиль» → «Проверка стримеров» → «Показать заявки». Откройте канал, сравните код с описанием, поставьте флажок и нажмите «Подтвердить стримера». «Снять галочку» отзывает подтверждение. Повторно копировать ID/URL/код в SQL не нужно. Панель и RPC доступны только аккаунту из `yndsi_private.owner`; обычный пользователь не может выдать галочку даже прямым вызовом API. Переданный снимок URL+кода проверяется повторно сервером, чтобы не одобрить изменившуюся заявку.

Кнопки копирования сначала используют Clipboard API, затем обычное выделение/копирование. Если браузер запрещает оба способа, открывается поле с текстом для ручного копирования долгим нажатием. Эта же логика исправляет кнопку копирования собственного ID в друзьях.

Ниже оставлен резервный способ для администратора базы.


Пользователь получает случайный код в настройках профиля и размещает его в публичном описании своего Twitch/YouTube-канала. SQL сохраняет заявку; галочка сама себе не выдаётся. В SQL Editor список заявок:

```sql
select p.code,p.name,v.channel,v.proof,v.requested_at
from yndsi_private.creator_verifications v
join yndsi_private.social_profiles p using(user_id)
where not v.verified order by v.requested_at;
```

Вручную откройте **точный URL из заявки**, убедитесь, что код виден в описании именно этого канала. Проверяется владение каналом, не личность/качество контента. После проверки скопируйте постоянный ID и точные URL/код в запрос (замените значения):

```sql
update yndsi_private.creator_verifications v
set verified=true,reviewed_at=now()
from yndsi_private.social_profiles p
where p.user_id=v.user_id and p.code='ID_ПОЛЬЗОВАТЕЛЯ'
and v.channel='ПРОВЕРЕННЫЙ_URL' and v.proof='ПРОВЕРЕННЫЙ_КОД';
```

Если изменился URL или код, запрос не подтверждает старую заявку. Отозвать галочку: аналогичный запрос с `verified=false`. Не выдавайте клиенту service_role или доступ к приватным таблицам. Менять verified может только администратор базы. Смена канала пользователем сбрасывает проверку.

## Напоминания

Подписаться можно на опубликованное расписание из профиля пользователя, дружба и галочка не обязательны. До 200 подписок на аккаунт. Списки подписчиков/подписок не публикуются. Скрытые расписания и заблокированные связи исключаются сервером. Даты передаются в UTC, сравнение с сегодняшним днём происходит на устройстве в выбранном пользователем часовом поясе; координаты не запрашиваются.

Проверка раз в минуту при открытом видимом сайте. Одно напоминание на эфир на данном браузере/аккаунте, повторное изменение эфира создаёт обновлённое напоминание. Баннер и опциональное системное уведомление. Это **не push при закрытом сайте** и не гарантия точной доставки. Для фоновой доставки нужен Web Push backend/планировщик; текущая версия его не содержит. Звук включён по умолчанию, доступен после взаимодействия с браузером; выключается в настройках уведомлений.

## Онлайн и скидки

«Сейчас на сайте» — приблизительное число активных браузеров за последние 90 секунд, включая гостей. Вкладки одного браузера объединяются случайным локальным токеном; авторизация не создаёт вторую запись. Токен обновляется через сутки. Координаты, аккаунт и IP в таблицу посетителей не записываются; API возвращает только число. Устаревшие токены удаляются при следующих запросах, не более 200 за раз. Фоновые вкладки прекращают heartbeat; посетитель исчезает со счётчика после тайм-аута. Разные устройства/браузеры одного человека считаются отдельно; это не проверка уникальных людей или ботов. При запрещённом хранилище вкладки могут учитываться отдельно. Кэш общего числа — 20 секунд, heartbeat — раз в 30 секунд. Приватный статус в чатах и общий агрегат независимы. Скидки приходят из Steam featured specials, регион KZ, цены в валюте ответа. Источник может быть недоступен — тогда показана ошибка, не фиктивные акции. Ссылки ведут на официальные скидки и новости распродаж Steam.

## Число подписчиков и звук

В своём и чужом профиле показано количество записей подписки на расписание, исключая заблокированные связи. Это серверное число: вкладки, просмотры, гости и дружба на него не влияют. Отписка уменьшает число. Имена подписчиков не выдаются. После применения 014 счётчик появляется без пересоздания аккаунта.

Приватность → Уведомления: звук включён по умолчанию, есть выключатель и кнопка «Проверить звук». Настройка отдельная для аккаунта на устройстве. Звук возобновляется после взаимодействия с приостановленным браузером, серии сигналов ограничены одним за две секунды. Браузер/iOS могут блокировать аудио; тест не гарантирует слышимость при выключенной громкости. При закрытом сайте сигналов нет.

## Отображение галочки (2.0.1)

Галочка видна рядом с ником в собственном профиле и его предпросмотре, публичном профиле, друзьях, поиске и списке/заголовке диалогов. Она берётся только из `yn_creator_profile.verified === true`; редактируемый профиль и локальные поля не выдают значок. Статусы видимых пользователей запрашиваются с ограничением параллельности и кэшем 30 секунд. После административного решения или смены канала кэш нужного ID обновляется немедленно. В собственном профиле есть явный текст состояния и кнопка «Обновить статус проверки». При недоступности проверки галочка не выдумывается; показывается сообщение о невозможности загрузить статус. Новых SQL для 2.0.1 не требуется.
