# Подключение Twitch к RIVLO

В разделе есть два источника: **Каналы Twitch** (официальный API Twitch, включая пользователей без аккаунта RIVLO) и **Профили RIVLO** (добровольно опубликованные профили нашего сайта). Для глобального поиска настройте серверные ключи Cloudflare; для связи своего аккаунта — провайдер Supabase. Это можно сделать с одним приложением Twitch.

## 1. База

После SQL 012/014 выполните [SQL 015](../supabase/migrations/202611080015_twitch_directory.sql) в Supabase → SQL Editor. Скрипт повторно запускается безопасно, существующие профили и ID не меняет. Видимость по умолчанию **выключена**, каналы сами в поиск не добавляются.

## 2. Приложение Twitch

Откройте https://dev.twitch.tv/console/apps и войдите в свой Twitch. Для Developer Console может потребоваться двухфакторная защита Twitch.

Выберите Register Your Application:

- Name: RIVLO (или другое свободное имя приложения).
- OAuth Redirect URL: `https://ougbjjfrxfokyqqriqtx.supabase.co/auth/v1/callback`.
- Category: Website Integration / подходящая категория сайта.
- Если есть Client Type: Confidential, потому что секрет хранит Supabase на сервере.

После создания откройте Manage. Скопируйте Client ID и создайте New Secret. **Client Secret не отправляйте в чат и не добавляйте в GitHub или код сайта.**

## 3. Supabase

Откройте https://supabase.com/dashboard/project/ougbjjfrxfokyqqriqtx/auth/providers → Twitch:

- включите Twitch Enabled;
- вставьте Client ID и Client Secret из Twitch;
- Save.

В Authentication → configuration options включите **Manual identity linking**. Это нужно, чтобы добавить Twitch к уже существующему аккаунту, включая Twitch с другой почтой. Сайт вызывает `linkIdentity`, а не создаёт ещё один аккаунт.

В URL Configuration (https://supabase.com/dashboard/project/ougbjjfrxfokyqqriqtx/auth/url-configuration) оставьте Site URL `https://yndsi-streamer-hub.pages.dev` и добавьте Redirect URL:

`https://yndsi-streamer-hub.pages.dev/?twitch=linked`

Twitch Developer Console принимает callback Supabase; настройки redirect в Supabase принимают адрес самого сайта. Не меняйте одно на другое.

## 4. Поиск по всему Twitch — Cloudflare

Выполните [SQL 016](../supabase/migrations/202611080016_twitch_channel_matches.sql) **после SQL 015** в Supabase → SQL Editor:
https://supabase.com/dashboard/project/ougbjjfrxfokyqqriqtx/sql/new

Откройте https://dash.cloudflare.com/ → Workers & Pages → **yndsi-streamer-hub** (Pages) → Settings → Variables and Secrets → Production.

Добавьте:

- `TWITCH_CLIENT_ID` — Client ID того же приложения Twitch (обычная серверная переменная).
- `TWITCH_CLIENT_SECRET` — Client Secret, тип **Secret / Encrypt**. Не вставляйте секрет в чат, GitHub, wrangler.jsonc или клиентские переменные.

Сохраните настройки. В Deployments → последняя Production-сборка → Retry deployment / Create deployment, чтобы Worker получил новые значения. Если интерфейс предлагает отдельное окружение Preview, не забудьте, что настройка Production относится к основному адресу.

Поиск `/api/twitch?q=логин` выполняется сервером через app access token. Пользователю не нужно входить в Twitch ради поиска. App token, Client Secret и почта не возвращаются браузеру. Результаты кратковременно кэшируются, одинаковые запросы объединяются, есть локальный ограничитель частоты. Он не заменяет распределённую защиту Cloudflare от DDoS.

Совпадение с RIVLO определяется **числовым ID Twitch из OAuth-привязки**, не текстом ника, не ссылкой, вписанной вручную, и не именем профиля. Владелец должен включить видимость канала. Скрытый/отвязанный профиль не выдаётся. Отсутствие результата не означает, что у человека вообще нет аккаунта: он мог скрыть связь. При ошибке проверки RIVLO интерфейс сообщает об ошибке, а не утверждает, что профиля нет.

Глобальный поиск Twitch возвращает каналы с эфирами за последние 6 месяцев. Дополнительно проверяем **точный логин** через Get Users: это позволяет найти давно неактивный зарегистрированный аккаунт. Разговорное имя вроде «Danger Лёха» не гарантирует совпадение — лучше использовать фактический логин или ссылку. На первой странице точное совпадение показывается первым. LIVE отображается только когда Twitch вернул реальный статус.

## 5. Проверка на телефоне

1. Войдите на сайт обычным способом.
2. Приватность → «Твой канал — в твоём профиле» → «Подключить Twitch».
3. Разрешите вход на официальной странице Twitch и вернитесь в RIVLO.
4. Проверьте «Подключён @ник». Постоянный ID, ник RIVLO и аватарка остаются прежними.
5. По желанию включите «Показывать мой канал в поиске стримеров RIVLO».
6. В боковом меню «Стримеры» → «Каналы Twitch» найдите реальный логин. Проверьте ссылку Twitch и кнопку «Профиль в RIVLO». Для поиска по имени сайта выберите «Профили RIVLO».
7. Проверьте канал, не связанный с сайтом: у него должна быть только кнопка Twitch. Выключите видимость своего канала — публичная связь исчезнет при новом поиске.

Гости видят только добровольно опубликованные профиль/канал и публичное расписание. Для подписки и общения нужен вход. Часовой пояс, почта, переписка, заметки и планы не публикуются. Привязка Twitch сама по себе не выдаёт административную галочку RIVLO — её прежнее правило проверки сохранено.

Отвязка выполняется через `unlinkIdentity`; Supabase требует ещё один способ входа, чтобы пользователь не потерял доступ. Если отвязка недоступна, сначала проверьте вход по почте. Снять видимость из поиска можно отдельным переключателем.

## Технические границы

Владение Twitch читается сервером только из `auth.identities` с provider=twitch, числовым provider_id и login, полученным от OAuth-провайдера. Поля user_metadata, ник RIVLO и присланная ссылка не являются OAuth-доказательством. Пользователи не имеют доступа к приватным таблицам. Twitch access/refresh tokens не сохраняются в локальном хранилище вместе с сессией RIVLO, не публикуются и не отправляются нашим RPC. Автоматического импорта никнейма/аватара и переименования профиля нет.

Глобальный поиск работает через серверный Helix API после добавления ключей Cloudflare. Незарегистрированные в RIVLO каналы имеют только ссылку Twitch. Список не включает весь Twitch сразу, используются запрос и пагинация. Не показываем выдуманный live-статус. Подключение на настоящем Twitch нельзя проверить до настройки вашего приложения; локальные проверки используют имитацию OAuth-ответов, настоящую SDK-форму вызова и PostgreSQL-проверки прав.

Официальные инструкции: https://supabase.com/docs/guides/auth/social-sign-in/auth-twitch и https://supabase.com/docs/guides/auth/auth-identity-linking .
