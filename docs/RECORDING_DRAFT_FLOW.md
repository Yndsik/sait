# Recording draft flow

Tapping Voice or Video message requests the required permission and starts recording automatically after permission is granted. Video no longer waits for a second Start button. Camera playback is muted; canvas capture supports switching cameras while recording where the browser supports it, with the existing native-stream fallback otherwise. If preview playback is rejected, recording falls back to the native camera stream instead of capturing an unplayed canvas. Existing pause/stop, 30-second video and 120-second voice limits remain.

Stopping closes the recorder dialog and docks a local unsent preview above the message composer. The user can play it, add an optional caption, discard it or press the regular Send button. Merely stopping or playing a preview never uploads/sends it. Voice playback/speed buttons explicitly use type=button inside the composer form. Rerendering the same chat preserves its pending recording. Leaving/changing chats or accounts cancels it and releases resources. A failed upload/send preserves the existing attachment identity and local draft for retry.

After a confirmed send, the chat refreshes and renders voice/video players directly. Private signed URLs are fetched near the viewport; no automatic audio playback is introduced. Video remains circular and can be expanded. A failed/expired media request has an explicit retry action. Photos use their own aspect ratio and a filled preview to avoid side bands; the large photo dialog preserves the full image.

Last-seen visibility already defaults to true in the presence schema. The privacy panel now labels last seen explicitly and preserves an existing opt-out. Friends and conversations expose server-confirmed status separately from unread/draft text. Unknown or hidden timestamps are never fabricated. These features require the existing presence SQL (009, after 008); this UI update introduces no new migration and does not reset saved privacy preferences.

Verification includes unit tests for automatic video startup/cancellation, draft send/discard routing, failure preservation and existing privacy opt-outs. A Chromium browser test used fake camera/microphone devices with real MediaRecorder output to verify automatic recording, unsent inline preview, preview playback without sending, rerender preservation, explicit composer send and inline playback. Actual iPhone Safari and physical Android permission/camera switching behaviour remain device acceptance checks.
